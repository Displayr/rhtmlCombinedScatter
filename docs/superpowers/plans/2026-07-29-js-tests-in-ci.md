# JS Tests in CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make GitHub Actions run the JS unit tests and the puppeteer visual regression suite alongside the existing nix R build, gating merges to master.

**Architecture:** A new `.github/workflows/js-tests.yaml` with two parallel jobs — a fast `unit` job (lint, jest unit tests, bundle build) and a slow `visual` job (puppeteer image-snapshot regression). The existing `build-r-package.yaml` is untouched. Puppeteer is upgraded from 3.3.0 to 24 via an npm `overrides` entry so a modern Chrome runs on a supported runner image; the one API this removes, `page.waitFor`, is restored by a local prototype shim rather than by modifying the shared rhtmlBuildUtils repo. Snapshot baselines are regenerated on the runner and committed back by a manual `workflow_dispatch`.

**Tech Stack:** GitHub Actions, Node 22, npm `overrides`, gulp 4 (via rhtmlBuildUtils 7.2.6), jest 26, puppeteer 24, jest-image-snapshot 3.1.0.

**Spec:** `docs/superpowers/specs/2026-07-29-js-tests-in-ci-design.md`

## Global Constraints

- Branch is `cc-fix-ci`. Do not commit to `master`.
- **Do not modify anything under `node_modules/`**, especially `node_modules/rhtmlBuildUtils/`. It is a shared dependency pinned at `github:Displayr/rhtmlBuildUtils#7.2.6`. All fixes are repo-local.
- Node version in CI is **22**. Runner is **`ubuntu-24.04`**, pinned — never `ubuntu-latest`.
- Snapshot env directory name is **`ci`**. The rename from `travis` is already done (commit `c241149`).
- **`--env=ci` must never be passed on a command line.** rhtmlBuildUtils declares `yargs.option('env', { choices: ['local', 'travis'] })`, so yargs rejects `ci`. The env is set in `build/config/widget.config.js` and the flag is omitted.
- Both CI jobs must run every test step even after an earlier step fails. Use `if: ${{ !cancelled() && steps.install.outcome == 'success' }}`.
- Neither job uses `continue-on-error`. Both are intended to be required checks for merging to master.
- The regenerated-baselines commit must be its own commit, containing nothing else, so git pairs the PNGs as modifications for review.
- Commit messages end with:
  `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`

## Verified Facts

These were checked empirically against puppeteer 24.43.1 while writing this plan. Do not re-litigate them.

- `require('puppeteer').Page` **is** exported.
- `Page.prototype.waitFor` is `undefined` (removed). So is `waitForTimeout`.
- `CdpPage extends Page`, and assigning `Page.prototype.waitFor` **is** inherited by `CdpPage` instances.
- `Page.prototype.close` and `Page.prototype.mouse` are `undefined` on the abstract base — they are implemented on `CdpPage`. This is expected and is **not** a problem.
- Still present: `Page.prototype.{goto,evaluate,click,type,$,$$,waitForFunction,screenshot}`, `Browser.prototype.pages`, `ElementHandle.prototype.screenshot`.
- puppeteer 24 requires Node `>=18`.
- The only `page.waitFor` call sites are `theSrc/test/bin/resize.jest.test.js:44,70,91` and `node_modules/rhtmlBuildUtils/src/lib/renderExamplePageTest.helper.js:106`.
- Snapshot path is `basePath / snapshotDirectory / env / branch / <collection>`, resolved by `_.defaultsDeep({basePath}, {snapshotTesting: <CLI args>}, build/config/widget.config.js, default.widget.config.js)`.
- `gulp testSpecs` roots at `theSrc/scripts` only. `gulp testVisual` roots at `.tmp` and `theSrc/test/bin`.
- Baseline: 8 suites / 86 tests pass via `npx gulp testSpecs` on Node 22.

- [ ] **Step 4: Write the shim**

Create `theSrc/test/jest.setup.js`:

```js
// rhtmlBuildUtils 7.2.6 calls page.waitFor(ms) in
// src/lib/renderExamplePageTest.helper.js, an API puppeteer removed. We pin
// puppeteer forward via an overrides entry rather than modifying that shared
// repo, so restore the method here instead.
//
// Only the numeric form is used. Defined on Page.prototype, which CdpPage
// inherits from. No-ops if a future puppeteer reinstates the method.
//
// This file is also loaded for `gulp testSpecs`, where puppeteer is
// irrelevant, so the require is guarded.
let Page
try {
  ;({ Page } = require('puppeteer'))
} catch (e) {
  Page = null
}

if (Page && typeof Page.prototype.waitFor !== 'function') {
  Page.prototype.waitFor = function (milliseconds) {
    if (typeof milliseconds !== 'number') {
      throw new TypeError(
        `waitFor shim supports only the numeric form, got ${typeof milliseconds}. ` +
        'Use waitForSelector or waitForFunction instead.'
      )
    }
    return new Promise(resolve => setTimeout(resolve, milliseconds))
  }
}
```

### Task 2: Add the `unit` CI job

Delivers the fast, deterministic half of the CI signal on its own.

**Files:**
- Create: `.github/workflows/js-tests.yaml`

**Interfaces:**
- Consumes: the `jest` config and `overrides` from Task 1.
- Produces: a workflow file with a `unit` job. Task 3 appends a `visual` job to the same file; Task 4 adds the `workflow_dispatch` input.

- [ ] **Step 1: Create the workflow with the unit job**

Create `.github/workflows/js-tests.yaml`:

```yaml
name: JS tests

on:
  push:
  workflow_dispatch:

jobs:
  unit:
    name: Unit tests and lint
    runs-on: ubuntu-24.04
    env:
      # This job never launches a browser, so skip the ~150MB Chrome download.
      PUPPETEER_SKIP_DOWNLOAD: 'true'
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm

      - name: Install dependencies
        id: install
        run: npm ci

      # Every test step below runs even if an earlier one failed, so a single
      # failure does not hide the rest. The job still reports red. Gated on the
      # install succeeding, so a broken npm ci does not cascade.
      - name: Lint
        if: ${{ !cancelled() && steps.install.outcome == 'success' }}
        run: npx gulp lint

      - name: Unit tests
        if: ${{ !cancelled() && steps.install.outcome == 'success' }}
        run: npx gulp testSpecs

      - name: Build widget bundle
        if: ${{ !cancelled() && steps.install.outcome == 'success' }}
        run: npx gulp build
```

### Task 3: Add the `visual` CI job

**Files:**
- Modify: `.github/workflows/js-tests.yaml`

**Interfaces:**
- Consumes: `snapshotTesting.env: 'ci'` and `snapshotTesting.puppeteer.args` from Task 1.
- Produces: a `visual` job. Task 4 adds the `update_snapshots` conditional steps to it.

- [ ] **Step 1: Append the visual job**

Add to `.github/workflows/js-tests.yaml`, as a sibling of `unit` under `jobs:` (no `needs:`, so the two run in parallel):

```yaml
  visual:
    name: Visual regression tests
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm

      # Pinned explicitly so text metrics do not drift with the base image.
      # Label placement is what this widget is for, and the pixel threshold is
      # 0.0001%, so a font change invalidates every baseline.
      - name: Install fonts
        run: |
          sudo apt-get update
          sudo apt-get install -y --no-install-recommends \
            fonts-liberation fonts-dejavu-core fonts-noto-color-emoji
          sudo fc-cache -f

      - name: Cache puppeteer browsers
        uses: actions/cache@v4
        with:
          path: ~/.cache/puppeteer
          key: puppeteer-${{ runner.os }}-${{ hashFiles('package-lock.json') }}

      - name: Install dependencies
        id: install
        run: npm ci

      # No --env flag: rhtmlBuildUtils constrains --env to ['local', 'travis'],
      # so 'ci' comes from build/config/widget.config.js instead. --branch is
      # likewise omitted, defaulting to master, so every branch compares
      # against master's baselines.
      - name: Visual regression tests
        if: ${{ !cancelled() && steps.install.outcome == 'success' }}
        run: npx gulp testVisual

      - name: Upload snapshot diffs
        if: ${{ !cancelled() }}
        uses: actions/upload-artifact@v4
        with:
          name: snapshot-diffs
          path: theSrc/test/snapshots/ci/**/__diff_output__/**
          if-no-files-found: ignore
          retention-days: 14
```

### Task 4: Add the `update_snapshots` dispatch

Lets CI regenerate baselines and commit them back, since Windows-generated snapshots can never match a Linux runner.

**Files:**
- Modify: `.github/workflows/js-tests.yaml`

**Interfaces:**
- Consumes: the `visual` job from Task 3.
- Produces: a `workflow_dispatch` input named `update_snapshots` (boolean). Task 5 triggers it.

- [ ] **Step 1: Add the dispatch input**

Replace the `on:` block at the top of `.github/workflows/js-tests.yaml`:

```yaml
on:
  push:
  workflow_dispatch:
    inputs:
      update_snapshots:
        description: 'Regenerate visual baselines and commit them to this branch'
        type: boolean
        default: false
```

- [ ] **Step 2: Grant the visual job write access**

Add to the `visual` job, as a sibling of `runs-on`:

```yaml
    permissions:
      contents: write
```

- [ ] **Step 3: Make the test step skip when regenerating, and add the regeneration step**

In the `visual` job, change the existing test step's condition to exclude regeneration runs:

```yaml
      - name: Visual regression tests
        if: ${{ !cancelled() && steps.install.outcome == 'success' && !inputs.update_snapshots }}
        run: npx gulp testVisual
```

Then insert this immediately after it, before the artifact upload:

```yaml
      - name: Regenerate baselines
        if: ${{ !cancelled() && steps.install.outcome == 'success' && inputs.update_snapshots }}
        run: npx gulp testVisual -u
```

On a `push` event the `inputs` context is empty, so `inputs.update_snapshots` is null and `!inputs.update_snapshots` is true — the normal test step runs and the regeneration step does not.

- [ ] **Step 4: Add the commit-back step**

Add at the end of the `visual` job's steps, after the artifact upload:

```yaml
      # Deliberately runs even if the regeneration step exited non-zero: a
      # partial regeneration is still worth capturing, and the uploaded diffs
      # show what failed. Review the commit before merging.
      - name: Commit regenerated baselines
        if: ${{ !cancelled() && inputs.update_snapshots }}
        run: |
          git config user.name 'github-actions[bot]'
          git config user.email 'github-actions[bot]@users.noreply.github.com'
          git add theSrc/test/snapshots/ci
          if git diff --cached --quiet; then
            echo 'No baseline changes to commit'
            exit 0
          fi
          git commit -m 'Regenerate visual regression baselines'
          git push origin HEAD:${{ github.ref_name }}
```

- [ ] **Step 5: Validate the YAML**

Run:
```bash
node -e "
const fs=require('fs');
const s=fs.readFileSync('.github/workflows/js-tests.yaml','utf8');
for (const needle of ['update_snapshots','contents: write','testVisual -u','github.ref_name']) {
  if(!s.includes(needle)) throw new Error('missing: '+needle);
}
if(!s.includes('!inputs.update_snapshots')) throw new Error('test step must skip on regeneration runs');
console.log('OK');
"
```
Expected: `OK`

- [ ] **Step 6: Confirm `__diff_output__` cannot be committed as baselines**

The commit step stages all of `theSrc/test/snapshots/ci`. On a failed regeneration run, jest-image-snapshot writes `__diff_output__/` directories alongside the baselines, and those must not be committed as if they were baselines.

`.gitignore` currently does **not** cover them — expect this check to print `NOT IGNORED`:

```bash
git check-ignore -v theSrc/test/snapshots/ci/master/resize/__diff_output__/x.png || echo "NOT IGNORED"
```

Add to `.gitignore`:
```
__diff_output__
```

Then re-run the check. Expected: it now prints a `.gitignore:<line>:__diff_output__` match instead of `NOT IGNORED`.

Note this also protects the pre-existing `theSrc/test/snapshots/local/` tree, where the `deleteDiffs` npm script exists precisely because these directories accumulate untracked.
